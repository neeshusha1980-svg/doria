# Doria Independent Platform — Security Audit Report

## 1. Security Hardening Summary

| Security Control | Implementation Location | Enforcement Details |
| :--- | :--- | :--- |
| **Verified-Email Admin Authorization** | `apps/api/src/auth/guards.ts` (`requireDoriaAdmin`) | Rejects with `403` unless `user.emailVerified === true` **AND** `user.email.toLowerCase()` is present in `env.ADMIN_EMAIL_LIST`. |
| **Zero Hardcoded Admin Emails or Weak Secrets** | `apps/api/src/config/env.ts`, `.env.example`, `docker-compose.yml` | `ADMIN_EMAILS` defaults to `""` (zero admins unless explicitly configured). `BETTER_AUTH_SECRET` (>= 32 chars), `DATABASE_URL`, and `S3_*` reject example placeholder strings (`change_me`, `replace_with`, `doria_dev_secret`) in `development` and `production`. |
| **Safety Profile & Guardian Enforcement** | `apps/api/src/auth/guards.ts` (`requireSafety`, `requireGuardianPermission`, `requireMultiplayerSafety`) | Authentication alone never satisfies `requireSafety`. Every protected route initializes/verifies `safety_profiles.status` (`'standard'` or `'active'` allowed; `'suspended'` blocked with `403`) and loads `parental_settings`. Guardian flags enforce `allowFriendRequests` (both on `POST /api/friends` and `PUT /api/friend-requests/:id`), `allowMoments`, `allowChat`, `allowAi`, and `supervisedAccess === true` + active `guardianUserId` for multiplayer. |
| **Neo AI HTML Sanitization & Usage Metering** | `apps/api/src/routes/ai.ts`, `apps/api/src/services/profiles.ts` | Server-side `isSafeGeneratedGameHtml()` blocks `<iframe>`, `<object>`, `<embed>`, `<form>`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `document.cookie`, `localStorage`, `sessionStorage`, `window.parent/top/opener`, and external `http(s)://` URLs before returning HTML, restoring reserved credits on rejection. |
| **CSRF & Cross-Origin Protection** | `apps/api/src/app.ts` (`onRequest` hook) | Validates `Origin` / `Referer` against `CORS_ORIGINS` and `BETTER_AUTH_URL` on all `POST`, `PUT`, `PATCH`, and `DELETE` requests, and rejects cookie-authenticated mutations missing an `Origin` header in production. |
| **Session Cookies & Rate Limiting** | `apps/api/src/auth/better-auth.ts`, `apps/api/src/app.ts` | HTTP-only cookies (`httpOnly: true`, `sameSite: 'lax'`, `secure: NODE_ENV === 'production'`, `cookieCache.enabled: false` for immediate revocation). Global rate limit (`120/min`) plus strict per-route limits on `/api/auth/*` (`20/min`), `/api/neo/generate` (`10/min`), `/api/moments` (`15/min`), `/api/badges` (`15/min`), `/api/parental/invitations*` (`10/min`), and `/api/reports` (`15/min`). |
| **WebSocket Authorization & Live Re-Check** | `apps/api/src/routes/multiplayer.ts`, `apps/api/src/realtime/hub.ts` | Validates `Origin` header and session on `/ws` upgrade, verifies `safety_profiles` status, caps connections at 5 per user, enforces room & guardian permissions on `POST /api/subscriptions`, and re-evaluates recipient chat/multiplayer permissions and bidirectional blocks on every message delivery. |
| **Administrator Audit Trail & Suspension** | `apps/api/src/db/schema.ts` (`admin_audit_logs`), `apps/api/src/routes/safety-admin.ts` | Persists immutable audit entries (`admin_user_id`, `admin_email`, `action`, `target_type`, `target_id`, `details`, `created_at`) for all admin mutations and adds `PUT /api/admin/users/:id/safety` and `GET /api/admin/audit-logs`. |
| **Database & Container Network Isolation** | `docker-compose.yml`, `apps/api/src/db/migrations/0000_initial.sql`, `0001_security_hardening.sql` | PostgreSQL (`5432`), MinIO (`9000`/`9001`), and API (`4000`) bind exclusively to `127.0.0.1` on the Docker host while Caddy fronts public ingress. All domain tables enforce `CHECK` constraints (`starlits >= 0`, `plays >= 0`), `UNIQUE` constraints, and `ON DELETE CASCADE` foreign keys. |

## 2. Verification Notes
